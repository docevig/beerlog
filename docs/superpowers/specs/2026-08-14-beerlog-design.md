# beerlog — дневник выпитого пива (Telegram Mini App)

Дата: 2026-08-14
Статус: дизайн утверждён, готов к планированию реализации

## 1. Что это

Личный дневник выпитого пива с прикладной статистикой, работающий как Telegram Mini App.
Тон — развлекательный: приложение показывает, что и сколько ты пил, но не морализирует,
не выставляет лимитов и не считает промилле.

Три этапа развития, каждый самостоятельно полезен:

| Этап | Содержание | Инфраструктура |
|---|---|---|
| 1. Дневник | Отметка «объём + стиль», история, правка, статистика, экспорт | GitHub Pages + Telegram CloudStorage |
| 2. Сорта | Названия, пивоварни, история сортов, повтор отметки | то же |
| 3. Сеть | Друзья, общие вечеринки, сравнение | + Cloudflare Workers + D1 |

Настоящий документ описывает **этап 1** и закладывает точки расширения под этапы 2 и 3.

## 2. Ключевые решения и обоснования

### 2.1 Telegram Mini App вместо PWA или нативного приложения

Друзья и совместные вечеринки — заявленная цель третьего этапа. Telegram даёт идентификацию
пользователя, готовый граф друзей и шаринг в чат без собственной системы аккаунтов.
Цена решения: приложение работает только внутри Telegram и требует HTTPS-хостинга с
фиксированным доменом.

### 2.2 Отсутствие бэкенда на этапах 1 и 2

Mini App — статическая страница. Данные хранятся в Telegram CloudStorage: они привязаны
к паре «пользователь + бот», синхронизируются между устройствами пользователя и переживают
переустановку клиента. Собственный сервер не нужен ни для хранения, ни для авторизации.

Валидация `initData` на этих этапах не требуется: подделать её пользователь может только
в ущерб собственным данным. Валидация появится на этапе 3 вместе с сервером, где чужие
данные станут доступны.

### 2.3 Слой хранилища с тремя реализациями

Прикладной код работает с интерфейсом `Storage`, а не с CloudStorage напрямую:

- `CloudStorage` — основная реализация, когда приложение открыто в Telegram;
- `LocalStorage` — фолбэк для запуска в обычном браузере (разработка) и для клиентов
  старее Bot API 6.9, где CloudStorage отсутствует;
- `RemoteStorage` — появится на этапе 3, прикладной код при этом не меняется.

Реализация выбирается один раз при старте по наличию `window.Telegram.WebApp.CloudStorage`.

### 2.4 Раскладка данных по ключам

Ограничения CloudStorage: до 1024 ключей на пользователя, ключ 1–128 символов из
`A-Z a-z 0-9 _ -`, значение до 4096 символов.

| Ключ | Содержимое |
|---|---|
| `meta` | Версия формата данных, дата последней записи |
| `profile` | Пресеты объёмов, порядок стилей, настройки |
| `log_YYYY_MM` | Все отметки за месяц, упакованный массив |
| `log_YYYY_MM_2`, `_3`, … | Продолжение месяца при переполнении 4096 символов |

Отметка в компактном виде занимает около 25 символов, то есть в один ключ помещается
примерно 150 записей за месяц. Слой хранилища при записи проверяет длину значения и
заводит следующий сегмент автоматически. Чтение месяца собирает все его сегменты.

Тысяча ключей при такой раскладке покрывает десятилетия истории.

### 2.5 Граница суток в 06:00

День для статистики начинается в 06:00 по локальному времени пользователя, а не в полночь.
Кружка, выпитая в час ночи, относится к предыдущему вечеру. Без этого теплокарта,
подсчёт трезвых дней и серий систематически врут на каждой пятнице.

Хранится всегда абсолютный `ts`; смещение применяется только при агрегации.

### 2.6 Экспорт данных

Полная выгрузка истории в JSON одной кнопкой. Данные лежат в чужой инфраструктуре,
и путь к их извлечению должен существовать с первого дня.

## 3. Модель данных

### 3.1 Отметка

```ts
interface Entry {
  id: string        // локальный уникальный идентификатор
  ts: number        // unix-время в миллисекундах, когда выпито
  ml: number        // объём в миллилитрах
  style: string     // код стиля из справочника
  abv?: number      // крепость, только если переопределена вручную
  name?: string     // название пива (этап 2)
  brewery?: string  // пивоварня (этап 2)
  rating?: number   // оценка 1–5
  price?: number    // цена в рублях
  place?: string    // место
  note?: string     // заметка
}
```

Обязательны `id`, `ts`, `ml`, `style`. Поле `abv` пишется только при ручном переопределении:
это экономит место и позволяет уточнять справочник стилей, не переписывая историю.

### 3.2 Справочник стилей

Около 20 позиций, каждая с кодом, названием и дефолтной крепостью. Справочник лежит
в одном файле исходников и правится там же.

| Код | Название | ABV, % |
|---|---|---|
| `lager` | Лагер | 4.5 |
| `pilsner` | Пилснер | 4.8 |
| `wheat` | Пшеничное | 5.0 |
| `unfiltered` | Нефильтрованное | 4.5 |
| `apa` | APA | 5.5 |
| `ipa` | IPA | 6.5 |
| `neipa` | NEIPA | 6.5 |
| `dipa` | Двойной IPA | 8.0 |
| `porter` | Портер | 5.5 |
| `stout` | Стаут | 6.0 |
| `imperial_stout` | Имперский стаут | 9.0 |
| `ale` | Эль | 5.0 |
| `belgian` | Бельгийское | 7.0 |
| `sour` | Сауэр | 4.5 |
| `gose` | Гозе | 4.5 |
| `fruit` | Фруктовое | 5.0 |
| `bock` | Бок | 6.5 |
| `dunkel` | Дункель | 5.0 |
| `barleywine` | Барливайн | 10.0 |
| `nonalc` | Безалкогольное | 0.5 |
| `cider` | Сидр | 5.0 |

### 3.3 Производные величины

- Объём за период: сумма `ml`.
- Чистый спирт в граммах: `ml × abv / 100 × 0.789`, где `abv` — переопределённая
  или дефолтная крепость стиля.
- Трезвый день: календарный день (с границей 06:00) без единой отметки.

## 4. Экраны

Нижняя навигация из трёх вкладок.

### 4.1 Отметить

Главный экран, оптимизирован под скорость: типовая запись — два тапа, повторная
кружка того же — один.

- Ряд пресетов объёма: 0,33 / 0,5 / 1,0 и кнопка произвольного значения.
- Блок «часто пьёшь»: 4–6 стилей, отсортированных по частоте в истории пользователя.
  Ниже раскрывается полный справочник.
- Оба поля запоминают последний выбор между сессиями.
- Кнопка «Записать» пишет отметку текущим временем.
- Ссылка «подробнее» раскрывает необязательные поля: название, пивоварня, место,
  оценка, цена, заметка. Там же можно сдвинуть время назад, если отмечаешь задним числом.

### 4.2 История

- Сводка за текущий день: объём, число порций, граммы чистого спирта.
- Лента отметок, сгруппированная по дням.
- Тап по записи — правка, свайп — удаление с возможностью отмены.
- Кнопка экспорта: выгрузка всей истории в JSON.

### 4.3 Статистика

- Карточки итогов: объём за неделю, месяц, год; трезвые дни; средняя порция;
  самый ударный день.
- Теплокарта месяца: сетка дней, насыщенность клетки пропорциональна объёму,
  пустая клетка — трезвый день.
- Разбивка по стилям: горизонтальные столбики с долями за выбранный период.
- Ачивки и сравнения: «попробовано N стилей из 21», «за год выпито столько-то ванн»,
  самая длинная серия трезвых дней, самая длинная серия дней подряд с отметкой.
  Итоговая карточка пригодна для шаринга в чат.

## 5. Технический стек

- Vue 3 + Vite + TypeScript.
- Без UI-фреймворка: экранов мало, а Telegram задаёт собственные CSS-переменные темы,
  под которые проще написать свои компоненты, чем перекрашивать чужие.
- Оформление наследует тему Telegram через переменные `--tg-theme-*`, поэтому
  приложение выглядит одинаково уместно в светлой и тёмной теме клиента.
- Хостинг: GitHub Pages, деплой из GitHub Actions по пушу в основную ветку.
- Бот создаётся в BotFather; обработчик сообщений ему не нужен — Mini App
  открывается кнопкой меню.

Ограничение платформы: приложение должно загружаться быстрее 10 секунд, поэтому
бандл держим минимальным и без тяжёлых зависимостей.

## 6. Границы этапа 1

Сознательно не делается:

- **BAC и промилле.** Без веса, пола, времени и скорости всасывания это число
  выглядит точным, но им не является.
- **Напоминания, лимиты, «нормы».** Продукт заявлен как развлечение, а не как
  инструмент самоконтроля.
- **Фотографии.** В 4096 символов на ключ они не помещаются; для них нужно
  внешнее хранилище, то есть этап 3.
- **Справочник конкретных сортов.** Названия вводятся вручную как свободный
  текст; полноценный справочник с автодополнением — этап 2.

## 7. Что закладывается под будущие этапы

- Поля `name`, `brewery`, `rating` уже есть в модели — этап 2 их только раскрывает
  в интерфейсе и добавляет автодополнение по своей истории.
- `id` у каждой отметки — локально уникальный, что позволит на этапе 3 синхронизировать
  записи с сервером без коллизий.
- `meta.version` — точка входа для миграций формата данных.
- Интерфейс `Storage` изолирует прикладной код от способа хранения, поэтому появление
  сервера не затронет логику экранов.

## 8. Риски

| Риск | Реакция |
|---|---|
| CloudStorage недоступен в старом клиенте | Фолбэк на localStorage, предупреждение о том, что данные не синхронизируются |
| Переполнение ключа в активный месяц | Автоматическая сегментация ключей в слое хранилища |
| Потеря доступа к данным Telegram | Экспорт в JSON доступен с первого релиза |
| Смена часового пояса пользователем | Хранится абсолютный `ts`, агрегация считается по текущему поясу |
